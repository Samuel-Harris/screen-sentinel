[OpenCode](https://github.com/opencode-ai/opencode) is a powerful terminal-based AI coding assistant written in Go. it implements the [Agent Skills](https://opencode.ai/docs/skills) open standard, which means Screen Sentinel skills work out of the box.

## setup

OpenCode discovers skills from multiple locations. copy the Screen Sentinel skills to any of these:

### option 1: project-level

```bash
# copy to current project
mkdir -p .opencode/skills
cp -r /path/to/screen-sentinel/.claude/agents/* .opencode/skills/
```

### option 2: user-level (global)

```bash
# copy to home directory for all projects
mkdir -p ~/.opencode/skills
cp -r /path/to/screen-sentinel/.claude/agents/* ~/.opencode/skills/
```

### option 3: clone directly

```bash
# clone screen-sentinel and symlink skills
git clone https://github.com/Samuel-Harris/screen-sentinel ~/screen-sentinel
ln -s ~/screen-sentinel/.claude/agents ~/.opencode/skills/screen-sentinel
```

<Note>
OpenCode uses the same Agent Skills format as Claude Code. files in `.claude/agents/` work in `.opencode/skills/` and vice versa.
</Note>

## available skills

| skill | description |
|-------|-------------|
| `screen-sentinel-query` | search accessibility-first screen text, audio transcriptions, and UI events (keyboard input, clicks, app switches, clipboard) |
| `screen-sentinel-health` | check status, diagnose issues, verify permissions |
| `screen-sentinel-logs` | retrieve and analyze Screen Sentinel logs |

## usage

OpenCode automatically discovers installed skills. invoke them in your prompts:

```bash
# start OpenCode
opencode

> @screen-sentinel-query find what I was reading about docker compose

> @screen-sentinel-health check if recording is working

> @screen-sentinel-logs show me errors from today
```

or let OpenCode choose automatically:

```bash
> what was I working on in VS Code this morning?
# OpenCode will invoke screen-sentinel-query

> is my screen recording working?
# OpenCode will invoke screen-sentinel-health
```

## MCP alternative

OpenCode also supports MCP servers. if you prefer MCP over skills:

```bash
# add to your opencode config
opencode config mcp add screen-sentinel "npx -y screen-sentinel-mcp"
```

<Tip>
skills are more token-efficient than MCP. the OpenCode team recommends skills for most use cases, with MCP for external API integrations.
</Tip>

## skill format reference

Screen Sentinel skills follow the Agent Skills standard:

```markdown
---
name: screen-sentinel-query
description: Query screen recordings and audio transcriptions
tools:
  - Bash
  - WebFetch
---

# Screen Sentinel Query Agent

Instructions for querying screen-sentinel data...
```

you can customize these skills or create your own following the same format.

## requirements

- Screen Sentinel running on localhost:3130
- OpenCode installed (`go install github.com/opencode-ai/opencode@latest`)
- skills copied to `.opencode/skills/` or `~/.opencode/skills/`

## troubleshooting

**skills not discovered?**
- run `opencode skills list` to see available skills
- verify files are in correct location with valid yaml frontmatter
- check skill file ends in `.md`

**queries returning no data?**
- verify Screen Sentinel is running: `curl http://localhost:3130/health`
- check data exists: `curl "http://localhost:3130/search?limit=1"`
- ensure Screen Sentinel has screen recording permissions

**OpenCode not using skills?**
- mention the skill explicitly: `@screen-sentinel-query find...`
- check skill description matches your query intent
